# Release 5B: Add New Pet from CareCard — Implementation Plan

**Date:** 2026-05-15  
**Status:** Plan Only — No Implementation Yet  
**Prerequisite:** Release 5A fully accepted  
**Objective:** Allow owner/admin to add a new pet to an existing client directly from CareCard.

---

## 1. Current API Capability Assessment

### Backend: `POST /admin/pets` — Already Supports Pet Creation ✅

The `pet_handler.py` handles both POST and PUT on the same code path:

```python
if not pet_id or pet_id == 'NEW':
    pet_id = str(uuid.uuid4())
    existing_item = {}
```

- If `pet_id` is absent or `'NEW'`, a new UUID is generated and a fresh PET# record is created
- Requires `client_id` in the body (used as the SK: `CLIENT#<client_id>`)
- All editable fields are accepted: name, species, breed, age, feeding_notes, medication_notes, behavior_notes, etc.
- RBAC: owner/admin/staff (staff has sensitive fields stripped)

### Frontend: `createPet(data)` — Already Exists ✅

```javascript
export const createPet = (data) => 
  request(`/admin/pets`, 'POST', data, true);
```

### API Gateway: `POST /admin/pets` — Already Routed ✅

Terraform confirms the route exists with Cognito authorization.

### Conclusion: **No backend changes needed.** The create-pet API is fully functional.

## 2. Backend Changes Needed

**None.** The existing `POST /admin/pets` endpoint handles creation. No new endpoints, no schema changes, no Terraform changes.

## 3. Recommended Create-Pet Flow

```
CareCard (approved record with linked client profile):
  → Admin clicks "+ Add Pet" button
  → Mini-form appears: name (required), species, breed, age
  → Admin fills in and clicks "Create Pet"
  → Frontend calls createPet({ client_id, name, species, breed, age, ... })
  → Backend creates PET# record with new UUID
  → Frontend refreshes CareCard to show new pet as additional tab
  → New pet appears in pet selector
```

### Key Details

- `client_id` for the new pet should be `pet._originItem?.linked_client_profile_id` (the Client Management profile ID) — same as existing pets for this client
- If `linked_client_profile_id` is not available, fall back to `pet._originItem?.client_id`
- After creation, re-fetch all pets via `handleSelectPet` to refresh the CareCard with the new tab

## 4. Data Model Fields for New PET# Records

The new PET# record will have:

| Field | Source | Required |
|-------|--------|----------|
| `PK` | `PET#<new-uuid>` (generated by backend) | Auto |
| `SK` | `CLIENT#<client_id>` (from form) | Auto |
| `pet_id` | New UUID | Auto |
| `client_id` | From CareCard context | Yes |
| `company_id` | From auth context | Auto |
| `entity_type` | `'PET'` | Auto |
| `name` | Admin input | **Required** |
| `species` | Admin input | Optional (default DOG) |
| `breed` | Admin input | Optional |
| `age` | Admin input | Optional |
| `is_active` | `true` | Auto |
| `created_at` | Now | Auto |
| `updated_at` | Now | Auto |

All other fields (feeding_notes, medication_notes, behavior_notes, health, quote fields, etc.) start as null/empty and can be edited later via the normal CareCard edit flow.

## 5. UI Behavior in CareCard

### Where the Button Lives

In the pet selector area (visible when CareCard is open for an approved record with a linked client profile):

```
[Joey] [Kyle] [+ Add Pet]
```

The "+ Add Pet" button appears:
- Only for owner/admin role
- Only when the record has a `linked_client_profile_id` or `client_id` that can own pets
- NOT during edit mode (same blocking as tab switching)

### Mini-Form

When clicked, shows a small inline form (or modal) with:
- Pet Name * (required)
- Species (dropdown: Dog, Cat, Other — default Dog)
- Breed (text input, optional)
- Age (number input, optional)
- [Create Pet] [Cancel] buttons

### After Creation

- Close the mini-form
- Re-fetch all PET# records for this client
- Refresh CareCard with updated `_allPets` array
- New pet tab appears in the selector
- Optionally auto-select the new pet tab

| Owner | ✅ Yes | Backend allows POST for owner |
| Admin | ✅ Yes | Backend allows POST for admin |
| Staff | ✅ Yes (limited) | Backend strips sensitive fields but allows creation |
| Client | ❌ No | Cannot access admin pet endpoint |

Frontend: Show "+ Add Pet" button only for owner/admin. Staff could technically create but we'll hide the button for simplicity (they can use the full Client Management flow if needed).

## 7. Idempotency / Duplicate Prevention

### Risk: Double-click creates two pets

**Mitigation:**
- Disable the "Create Pet" button after click (loading state)
- After successful creation, close the form immediately
- The backend generates a new UUID each time — there's no natural dedup key

### Risk: Same pet name created twice

**Acceptable for MVP.** Pet names aren't unique identifiers. If admin accidentally creates "Joey" twice, they can archive one via Release 5C (future). The system already handles multiple pets with the same name (Release 4A name-matching logic creates new records for ambiguous matches).
