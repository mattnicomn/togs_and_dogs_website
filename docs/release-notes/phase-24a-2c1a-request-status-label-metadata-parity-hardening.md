## 5. Dedicated Backend Parity Test Suite

Added dedicated test file: `tests/backend/test_phase24a_request_status_contract_parity.py` (13 focused tests):

1. `test_canonical_contract_file_exists_and_parses`: Validates JSON schema root keys and contract header.
2. `test_canonical_17_keys_and_exact_order`: Asserts exactly 17 canonical status keys in exact order.
3. `test_canonical_status_entry_fields_and_order`: Asserts exact field membership and `label` position as first property.
4. `test_canonical_status_labels_match_approved_map`: Asserts all 17 friendly labels match approved map exactly.
5. `test_canonical_categories_flags_and_synonyms`: Asserts category allowlist, booleans, and synonym arrays.
6. `test_web_adapter_request_statuses_parity`: Asserts web adapter `REQUEST_STATUSES` deep-equality and key order.
7. `test_mobile_adapter_request_statuses_parity`: Asserts mobile adapter `REQUEST_STATUSES` deep-equality and key order.
8. `test_web_and_mobile_adapters_equal_each_other`: Asserts web and mobile adapters equal each other.
9. `test_backend_request_status_enum_contains_17_canonical_keys`: Asserts all 17 canonical keys are present in backend `RequestStatus` enum in `src/backend/common/status.py`.
10. `test_backend_aliases_characterized_and_excluded_from_canonical`: Characterizes documented backend `RequestStatus` synonyms (`NEEDS_REVIEW`, `NEEDS_MG`, `NEW_REQUEST`, `QUOTED`, `BOOKED`) and asserts they are excluded from canonical contract keys.
11. `test_job_status_domain_separated_from_request_contract`: Asserts `JobStatus` is a separate 6-member enum (`JOB_CREATED`, `ASSIGNED`, `COMPLETED`, `CANCELLED`, `ARCHIVED`, `DELETED`).
12. `test_pseudo_actions_and_ui_values_excluded_from_canonical_contract`: Asserts pseudo-actions (`VERIFY_MEET_GREET`) and UI options (`IN_PROGRESS`, `RESCHEDULED`, `REJECTED`, `PENDING REVIEW`) are excluded from canonical keys.
13. `test_no_backend_generated_request_status_adapter_exists`: Asserts `generated_request_statuses.py` does not exist in Phase 2C.1A.
