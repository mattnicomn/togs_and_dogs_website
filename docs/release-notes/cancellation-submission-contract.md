## Proposed atomic persistence and identity contract

Operation identity binds domain/version, tenant, client, request, trusted issuer/actor, stable opaque operation key and exact reason. Missing reason uses existing `No reason provided.` intent; empty/whitespace strings are preserved, never silently trimmed. Explicit null/non-string reasons are refused in this model and require a compatibility decision. Expected revision, receipt timestamp and warning are not retry-payload inputs; retries retrieve the first committed result rather than recomputing them. Same operation changed reason/actor/target conflicts; distinct concurrent operations serialize on the REQUEST revision and source status. No identity inferred from display names/email. Full reason lives only in the intended REQUEST/audit; the receipt stores its digest binding, not a duplicate raw reason.

A future commit has exactly four distinct-item actions, all conditional:

1. **REQUEST Update**, never Put: exact key/existence, company/client/request fields, source status, strict Number revision, immutable incarnation, start_date value/presence, audit absent-or-LIST, concrete booking identity fields, and absence of every known canonical/provisioning marker. NULL/partial/unsupported markers refuse. Set only existing cancellation fields and next legacy_write_revision; atomically append the single audit entry. New unrelated fields and concurrent unrelated changes survive because no whole record is replaced.
2. **Reservation absence check** at PR50-compatible `RESERVATION#<SHA256([tenant,PK,SK])>/PERMANENT`.
3. **Lifetime check** at matching LIFETIME key: exact incarnation, BOOL false retirement, no ttl/expires_at. Missing, retired, reused or expiring lifetime refuses. No lifetime/reservation is created here.
4. **Create-only receipt Put** at tenant-scoped operation key, storing actor/issuer/target/payload binding, original incarnation/source revision/time/warning. REQUEST and receipt either both publish or neither does; there is no partial-success fallback.

Low-level transaction shapes are built offline only. Complete request budget is conservatively below 300 KiB using an encoded estimate; condition <=4096 bytes. Oversize refuses before state publication; no splitting, truncation or actual API payload-limit change. Integral finite DynamoDB Decimal revisions are explicitly parsed; booleans, floats, fractions, strings, negative/zero/overflow values refuse. Existing audit entries persist and malformed audit types refuse; audit append and receipt ensure one modeled submission audit despite identical replay.

Unversioned or identity-incomplete legacy records return LEGACY_ADAPTER_PENDING with zero enrollment/mutation. No migration, backfill, default incarnation or revision is manufactured. As in PR50, permanent witness integrity and complete writer coverage remain hard prerequisites: an old writer can still bypass retirement/revision conventions, and identical full storage rollback is not detectable. Field-preserving Update closes this operation's whole-record unknown-field loss; it does NOT close all legacy writer races or establish real storage durability. Shared review/cancellation/admin/payment/quote/manual/script writers, cleanup and backup restoration must be covered before activation.

## Replay, warning and ambiguous outcomes

Replay requires current trusted booking access against the currently read exact REQUEST and its live, non-expiring lifetime, plus the bound original receipt. It performs no mutation/audit and returns the original message/warning. It may report historical submission after a later admin decision without reopening the booking or claiming its current status. Old access revisions, revoked contexts, mismatched actors/targets/payloads, retired/missing lifetime or malformed receipts refuse. Real receipt authentication/integrity and strongly consistent read/reconciliation are future adapter obligations.

Trusted supplied time makes warning deterministic. Date-only input means midnight UTC as in the backend; strictly less than 24 hours is urgent, exactly 24 is not, and past dates are urgent under current backend behavior. Missing/empty/invalid ISO dates produce false as currently intended. Offset-aware timestamps compare by instant. Naive timestamp-with-time is explicitly NAIVE_TIMESTAMP_POLICY_PENDING rather than inventing a timezone; the existing handler can encounter a TypeError there. Web local-date prewarning differs, especially for past dates; aligning these surfaces needs separate approval. Warning is informational, not a fee determination. Original committed timestamp/warning remain stable on replay.

Confirmed conditional refusal is distinct from confirmed receipt replay and UNKNOWN_NO_BLIND_RETRY. Missing receipt after a timeout does NOT prove non-commit or that the old attempt has stopped. A timeout before the synthetic commit leaves no changes; a timeout after it is reconciled through the bound receipt without another audit. No automatic fresh key, unconditional retry, record deletion or compensating rewrite. Operator recovery always refuses OPERATOR_RECOVERY_AUTHORIZATION_PENDING; this package grants no operator action. Any future recovery must bind actor authority, exact tenant/client/request/operation/incarnation/version, audit and evidence of the old attempt's outcome/quiescence.
