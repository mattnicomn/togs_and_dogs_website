## Finding: Cache Pollution in Lambda Archive

The locally generated `infra/prod/backend.zip` (386 KB) contains **42 unintended cache/bytecode entries**:
- `.pytest_cache/` directory (4 files)
- `common/__pycache__/*.cpython-313.pyc` (multiple)
- `handlers/__pycache__/*.cpython-313.pyc` (multiple)
- `common/notifications/__pycache__/*.cpython-313.pyc`

These are generated by running tests locally and are NOT part of the intended Lambda deployment package.

## Current Configuration

```terraform
data "archive_file" "backend_zip" {
  type        = "zip"
  source_dir  = "${path.module}/../../src/backend"
  output_path = "${path.module}/backend.zip"
}
```

- **No `excludes` parameter configured** — archives everything in `src/backend/`
- Provider: `hashicorp/archive` v2.7.1
- All 13 Lambda functions reference this single archive

## Impact

- Archive hash is nondeterministic (varies based on local cache state)
- Running tests before `terraform plan` changes the archive hash
- Different developers/environments produce different hashes
- Cache files are deployed to Lambda but have no operational effect (Lambda uses Python 3.11, caches are cpython-313)
- The hash mismatch contributes to spurious Lambda update proposals in plans

## Options Assessed

### Option A — Archive `excludes` Parameter (RECOMMENDED)

```terraform
data "archive_file" "backend_zip" {
  type        = "zip"
  source_dir  = "${path.module}/../../src/backend"
  output_path = "${path.module}/backend.zip"
  excludes    = [
    "**/__pycache__/**",
    "**/*.pyc",
    "**/*.pyo",
    ".pytest_cache/**",
    ".hypothesis/**",
  ]
}
```

| Criterion | Assessment |
|-----------|-----------|
| Provider support | ✅ `excludes` supported since archive provider ~2.x (v2.7.1 installed) |
| Permanent enforcement | ✅ Prevents future cache pollution regardless of local state |
| Implementation complexity | Low — one parameter addition |
| Workflow change | None — `terraform plan` works normally |
| Risk | Low — well-established provider feature |
| Pattern semantics | Glob-style; requires verification of exact matching behavior during implementation |

**Note:** Exact glob matching semantics (whether `**/__pycache__/**` correctly matches nested directories) must be verified by AG during implementation. If glob depth is limited, explicit paths may be needed: `.pytest_cache/**`, `common/__pycache__/**`, `handlers/__pycache__/**`, `common/notifications/__pycache__/**`.

### Option B — Clean Tracked-File Staging Directory

| Criterion | Assessment |
|-----------|-----------|
| Determinism | Strongest — only explicitly staged files enter the archive |
| Implementation | High — requires scripted staging before archive generation |
| Maintenance | Medium — new source files must be included in staging logic |
| Justified | Not for this project's scale — over-engineered |

**Verdict:** Reserve for projects with complex multi-source packaging. Not needed here.

### Option C — Manual Cleanup Before Planning

| Criterion | Assessment |
|-----------|-----------|
| Enforcement | ❌ None — human-dependent |
| Reproducibility | ❌ Fragile — tests recreate caches |
| Long-term viability | ❌ Will recur |

**Verdict:** Temporary fallback only. Not acceptable as permanent control.
